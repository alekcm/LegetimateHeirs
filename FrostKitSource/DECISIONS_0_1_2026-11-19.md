# Зафиксированные решения для версии 0.1

**Источник решений:** ответы автора от 19 ноября 2026.
**Приоритет:** этот файл уточняет рабочий объём v0.1; он не отменяет прямые запреты на черновые/тестовые поздние категории из `Docs/FROSTPUNK2_CAMPAIGN_LAW_REDESIGN_v0.1.md`.

## 1. Игровой объём

**v0.1 — вертикальный срез**, а не вся кампания.

В него входит:

1. собственный scenario, созданный копированием developer sample;
2. вступление: письмо → приезд → скрытое известие о смерти отца;
3. активные с первой недели **«Двенадцать печатей»** из §1.2 redesign;
4. основной quest возрастной поправки;
5. одна полноценная временная фракционная линия, написанная агентом в рамках уже утверждённой темы и явно помеченная как материал v0.1;
6. promise этой линии, Council vote и проверка успешного/неуспешного результата;
7. private anniversary на неделе 52 и 52-недельный ultimatum до недели 104;
8. законная передача власти и первый выбор политической опоры;
9. PIE/save-load/cooked test.

В 0.1 не включаются Act II, Act III и категории, которые design document прямо помечает как «не реализовывай».

## 2. Временная фракционная линия

Автор разрешил агенту написать **временную v0.1-версию** конкретных долгов отца и обещания. Она не становится молча частью утверждённого канона.

Для первого среза используется линия **Порубежников**: она сразу проверяет ключевую тему центрального тепла и холодной периферии, а также действие печати `Неподвижный контур`.

Требование к материалу линии:

- две завершённые игровые задачи, связанные с уже установленными темами Порубежников: холодная периферия, жильё/тепло, практики выживания;
- одно ясное обещание в обмен на поддержку поправки;
- как минимум один отложенный эффект/флаг;
- все новые narrative IDs имеют префикс `LH_V01_PROVISIONAL_`;
- никакие детали не переносятся в «зафиксированный канон» без отдельного решения автора.

## 3. Возрастная поправка и 67%

Не создавать искусственную систему процентных весов Порубежников/Стражей/Основателей.

`Политика после пятидесяти` и `Право голоса после тридцати` должны жить в существующей ванильной ветке **Rule** — в ней все законы требуют 67% голосов «за». Реализация обязана использовать реальную Council/Rule механику текущей версии игры и не имитировать её собственным числом `AmendmentSupportPercent`.

Обещание Порубежникам в v0.1 должно применить только тот подтверждённый в editor механизм отношения/standing/voting behavior, который действительно влияет на Rule vote. Если такого механизма нельзя связать с пользовательской фракцией без подмены базовых assets, v0.1 сохраняет native Rule vote, а promise остаётся unlock/gate для вынесения закона на повестку; это должно быть явно отражено в UI, а не скрыто под фальшивыми процентами.

## 4. «Двенадцать печатей»

Все 12 custom start policies из §1.2 redesign должны быть активны **с первой недели без стартового голосования**:

| Law category | Start policy |
|---|---|
| Waste Heat Conversion | Неподвижный контур |
| Worker Shifts | Смена до падения |
| Scout Training | Недоукомплектация исследователей |
| Basic Necessities | Паёк ожидания |
| Housing Distribution | Запертые спальни |
| Outsiders | Закрытые ворота |
| Community Service | Инвентарь в долг |
| Maintenance Duty | Верховенство бумаги |
| Work Compensation | Расчёт долгом |
| Labour Organisation | Запрет на работу |
| Funerals | Безымянная яма |
| Childhood | Легализация беспризорничества |

Каждая печать добавляется как custom policy в **существующий** соответствующий базовый вопрос закона и становится его стартовым состоянием. При смене этой policy игрок получает **существующие базовые варианты Frostpunk 2** в той же категории. Черновые custom replacement laws из §1.3 не создаются.

Порядок editor-проверки:

1. дублировать текущий базовый `PXPolicyType` в нужной категории;
2. заменить name/description/effect/requirements в duplicate;
3. добавить policy в существующий `PXLawType` — не создавать параллельный новый вопрос;
4. назначить её default стартовой policy только для LH scenario;
5. проверить, что выбранный base-game alternative заменяет печать, а не складывается с ней;
6. если базовый asset надо изменить, применять проверенный Data Injection/deprecation workflow, а не перезаписывать shared asset.

## 5. Один незафиксированный числовой эффект

В §1.2 у печати **«Паёк ожидания»** буквально записано: `−20% сытость (или +2-% Hungry, я не знаю, как правильно)`. Это не готовое техническое значение и не имеет однозначного FrostKit modifier name.

До отдельного решения автора реализация не должна угадывать между:

- modifier Food Demand;
- Hunger statistic;
- иной процентной потребностью/need.

Все остальные одиннадцать печатей могут быть перенесены после editor-аудита доступных modifiers; их численные эффекты всё равно нужно проверить по реальным type/tag/modifier names FrostKit.
